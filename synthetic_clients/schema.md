## 2. Порядок генерации (кто от кого зависит)

```
пол × возраст ─┬─> федеральный округ ──> тип населённого пункта
               │                                │
               ├─> образование <────────────────┤
               ├─> занятость, работающий пенсионер, основание пенсии
               ├─> состав домохозяйства ──> дети до 18
               └─> инвалидность
доход ← тип НП, занятость, образование, дети
 «вне банков» ← возраст, тип НП, доход   (запись отбрасывается: шаг «население → клиенты»)
продукты ← возраст, доход, дети (ипотека), занятость (пенсия через банк)
смартфон и ОС ← возраст, тип НП, доход
приложение, интернет-банк ← возраст, тип НП, образование, наличие смартфона
цифровая грамотность ← возраст, образование, наличие смартфона
офис, телефон за 12 месяцев ← возраст, тип НП
жертва мошенничества ← (базовая доля; без связи с возрастом — источника нет)
обращения за 12 месяцев ← число продуктов, мошенничество, возраст, цифровая грамотность
предпочитаемый канал ← доступные каналы (приложение, веб), возраст, тип НП, цифровая грамотность
тема ← продукты, каналы, мошенничество, возраст, пенсия
решено сразу ← тема, канал;   эскалация ← только если не решено
CSAT ← решено сразу, эскалация, частые обращения, тема «мошенничество»
отношение к чат-боту ← возраст, цифровая грамотность, нерешённое последнее обращение
отношение к ИИ ← возраст (охват ИИ-сервисов, Mediascope)
NPS ← CSAT, возраст 55+;   доверие ← мошенничество, CSAT 1–2
финансовая тревожность ← доход, мошенничество, кредиты
родной язык ← федеральный округ
```

Как работают зависимости: в `config.yaml` каждая связь задана множителями («у 75+ в 0,25 раза чаще, чем в среднем»). Сначала генератор разыгрывает значения с этими множителями. Затем подбирает веса записей методом рейкинга (итеративная подгонка), чтобы итоговые доли совпали с целями. Получается, что **форму** связи задают допущения, а **уровень** — источники.

## 5. Антистереотипные ограничения (проверяются по каждой возрастной группе)

- Цифровая грамотность 4–5 у 65–74 и у 75+ — не меньше 10%. Грамотность 1–2 у 18–24 и 25–34 — тоже не меньше 10%.
- Отношение к чат-боту в каждой возрастной группе: позитивное — не меньше 15%, негативное — не меньше 20%.
- Пользуются приложением не меньше 25% людей 75+.
- CSAT 1–2 среди обращавшихся в каждой возрастной группе — не меньше 10%.
- Критики NPS в каждой возрастной группе — не меньше 8%.
- Доли негатива (CSAT 1–2, нерешённые обращения, критики) проверяются против целей отдельной строкой. Занижение больше чем на 1,5 п.п. считается ошибкой.

## 6. Веса и малые подгруппы

1. Ячейки для оверсэмплинга: возрастная группа × тип населённого пункта (7 × 5 = 35 ячеек). Если в ячейке меньше 150 записей, генератор добирает записи именно этой ячейки.
2. Базовый вес записи = (ожидаемая доля ячейки) / (фактическая доля ячейки в базе).
3. Затем рейкинг подгоняет веса под все цели: пол × возраст, ФО, тип НП, образование, занятость, доход, продукты, каналы, ОС, слой C и D.
4. Веса ограничиваются: не меньше 0,2 и не больше 5 от среднего. Это нужно, чтобы отдельные записи не «перевешивали» выборку. Если из-за ограничения какая-то цель не достигается, отклонение пойдёт в отчёт.
5. Ожидаемо малые ячейки: 75+ в Москве (≈0,7% → ~110 записей без добора), 75+ в СПб, 18–24 в СПб. Точный список даст пилот.

## 7. Качественный слой: как отбираются 300 персон

- Страты: возраст (18–34 / 35–54 / 55–69 / 70+) × тип НП (Москва и СПб / город 500 тыс.+ / город до 500 тыс. / село) × частота обращений (0 / 1–5 / 6+) × предпочитаемый канал (цифровой / телефон / офис). Всего 144 ячейки.
- Число персон в ячейке пропорционально корню из её взвешенного размера. Так малые, но важные группы не пропадают. Любая ячейка, где есть хотя бы 3 записи, получает минимум 1 персону.
- Людей без обращений — не больше 15% персон: интервью про поддержку.
- Для каждой персоны: биография (80–120 слов), типичная ситуация обращения, 2–3 фразы в её манере речи, болевые точки. Стиль общения — новая черта, только в качественном слое.
- Пишутся партиями по 25, строго из атрибутов записи.
